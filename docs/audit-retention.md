# Bounded audit retention

The audit writer preserves metadata-only JSONL, existing redaction, and fail-open
business behavior. It does not promise lossless or tamper-proof audit storage.
No collector, cloud resource, deployment, or live log deletion is part of this
source change. Operators must review the retention policy before rollout.

## Policy and capacity

Defaults are 10 MiB per file, five files **including the active file**, and a
maximum segment age of seven days. This is at most 50 MiB of managed file data
for a conforming single-writer set, not a disk quota: directory metadata,
filesystem allocation, snapshots, backups, and unrelated files are excluded.
Keep filesystem headroom. The file cap must fit the configured record cap.
Records are limited to 64 KiB by default, including their UTF-8 newline. Input
traversal is bounded before redaction/serialization; rejected records are not
truncated into misleading metadata.

The default queue admits at most 128 operations including the current write,
with each queued record at most 64 KiB (at most 8 MiB of queued encoded record
data, plus bounded serialization/runtime overhead). The hard settings cap is
256 operations and 64 KiB per record. A stalled filesystem cannot grow the queue
indefinitely, but asynchronous filesystem I/O has no hard completion deadline.

Capacity takes priority: older history may disappear before seven days. This is
**maximum age, not guaranteed minimum retention**. Guaranteed retention needs an
agreed traffic budget and durable external storage/export policy. Under the
existing fail-open policy, storage or queue failures can lose audit events.

## Ownership, names, and concurrency

`MCP_AUDIT_LOG_PATH` names the active file. Exact sibling names `.1` through `.31`
are reserved for this writer; `.1` is the newest archive. No directory scan or
wildcard cleanup is used. Unrelated names such as `.backup` are not touched.
Reducing the configured file count removes reserved excess generations after
validation. Only one process may own this path and its reserved names. Replicas
must use separate directories; do not combine this writer with external logrotate.

New files use mode 0600. Existing managed files must be regular, singly linked,
private files owned by the service UID. Leaf symlinks are not followed. The
parent directory and its ancestors must be trusted, operator-controlled paths;
path-based rename/unlink cannot defend against a malicious directory owner.
The service never changes existing file permissions to force access.

The writer preflights all 32 reserved names before each sweep. Append, cleanup,
and descending rotation share one bounded serialized queue. Rotation removes
the oldest generation before shifting the remaining files, so it creates no
extra temporary copy. A crash can leave numbering gaps or lose the retired
oldest generation; gaps are accepted on restart. It is not an atomic transaction
across the entire archive set and does not fsync each record.

## Age and restart behavior

Age is recovered from the first JSONL record's `ts`, generated by the gateway,
not file mtime, so continued appends and restarts do not reset retention. A new
record timestamp earlier than the active segment's first timestamp starts a new
segment. Entire expired segments are removed, which can remove newer records in
that segment before their own age limit.

Cleanup runs at startup, before append, and while idle every min(60 seconds,
configured max age). Idle sweeps coalesce and use the same queue. In a running,
healthy process with a correct wall clock, expiry is enforced on the next sweep;
queue/I/O delay adds to this interval. Offline processes, clock rollback/future
timestamps, or storage failures prevent a strict wall-clock deletion guarantee.
After restart, the next successful sweep resumes enforcement. Backups and
snapshots require their own retention policy.

If a completed first record is followed by a crash-partial final line, the
segment is archived without joining new JSON to that incomplete line. Consumers
must handle the archived partial tail; no repair claims are made. An incomplete
or malformed first record, unsafe file, or non-expired oversized existing file
stops audit persistence with diagnostics until the operator reconciles it.
Successful business calls still succeed. On a failed append, same-descriptor
rollback of that operation is attempted; failed rollback remains an error and
subsequent writes re-inspect the on-disk state. Records are never replayed.

## Failure visibility

`audit_write_failed` reports cumulative failed/rejected records for this process;
it can include a partially persisted record and is not an exact loss measurement.
`audit_maintenance_failed` separately counts failed sweep attempts. Each category
is sampled at most once per 60 seconds, with an initial warning. Neither includes
record content, file paths, identifiers, exception messages, or stacks. Warning
sink failures never recurse. Rotation/cleanup failures stop that append rather
than falling back to unbounded writes. Business status and readiness are unchanged.

## Deployment and migration

1. Agree the capacity/age settings and whether losing older history before that
   age is acceptable. Review any mandatory retention independently.
2. Stop the old writer before changing directories or sharing an existing set.
   Preserve any needed old history through an operator-approved backup procedure.
   Inventory the active file and all 31 reserved sibling names; never point the
   writer at a mixed-use directory or reserve names belonging to another service.
3. For Compose, provision a dedicated persistent host directory, private to the
   mapped service UID 10001 (typically mode 0700), and set the absolute
   `MCP_AUDIT_HOST_DIR` in the ignored `.env`. Host permissions/UID mappings,
   SELinux, rootless engines, and Docker Desktop need environment-specific checks.
   The long-form bind uses `create_host_path: false`; it never repairs permissions.
4. The new Compose template fixes the container path to
   `/var/log/arcsuite-mcp/audit.jsonl`, separate from `/tmp` and `/shared`.
   Existing ignored Compose files are not migrated automatically. Direct Node
   development keeps its previous path unless explicitly configured; production
   should choose private persistent storage.
5. Check directory write access as the actual gateway user before serving real
   traffic. Review normal audit events and sanitized failure diagnostics with
   synthetic data. Configure monitoring for both warning categories and disk use.
6. Existing malformed, overly permissive, or oversized logs are not silently
   truncated to fit a changed limit. Preserve/reconcile them while stopped before
   rollout. Old `/tmp` files are not copied or deleted automatically.

Changing source or passing local/CI fixtures does not qualify the operator's
actual UID mapping, storage, restarts, or Dify/MCP deployment. Those checks remain
operator-run. The default values are an adjustable starting policy, not an estimate
of production event volume. External log collection is a separate future change:
it also changes who can read audit metadata and how delivery loss is detected.
